# 记忆宫殿轻量控制台 · 多端点配置说明

> 适用页面：`/console.html`（轻量单页控制台）
> 目的：一个控制台访问多个部署节点，自动就近选点，单节点故障自动切换，不占额外资源。

## 1. 原理

控制台启动时并发探测所有候选端点的 `/api/palace/status` 接口：

- 选择 **延迟最低** 的可用节点作为当前节点；
- 请求中若发生**网络失败**或 **5xx** 错误，自动切换到下一个节点重试；
- 所有候选节点均不可用时，**回退到同源**（即当前页面所在域名），保证仍可用。

端点来源（合并去重，运行时可临时添加的优先）：

```
localStorage 自定义端点  +  构建注入端点(VITE_API_ORIGINS)
```

## 2. 配置方式（二选一，可叠加）

### 方式 A：部署时注入（推荐，GitHub Actions）

在 GitHub 仓库中设置 **Repository Variables**（不是 Secrets）：

```
Name:  VITE_API_ORIGINS
Value: https://gyuanpalace.xyz,https://lingdayun.cn
```

- 多个端点用**英文逗号分隔**，不要带末尾斜杠；
- 留空 = 同源模式（只访问控制台当前域名）；
- 部署流水线会自动把该值注入 `console.html`，无需改动代码；
- 修改后重新触发部署即生效；
- 完整 workflow 示例见 [deploy-gh-actions-example.yml](deploy-gh-actions-example.yml)。

### 方式 B：运行时添加（浏览器内，免部署）

1. 打开控制台，点击右上角 **⚙️ 设置**；
2. 在「🌐 API 端点」输入框填入完整地址（须以 `http(s)://` 开头），点击 **添加**；
3. 添加后自动重新探测并切换到延迟最低的节点，端点保存在本机浏览器（localStorage）；
4. 如需移除，点击端点右侧「移除」按钮。

> 说明：方式 B 只影响当前浏览器，适合临时接入新节点调试；正式环境推荐用方式 A 让所有用户共享。

## 3. 端点要求

| 要求 | 说明 |
| --- | --- |
| 必须 HTTPS | 除本地开发外，浏览器安全策略要求 HTTPS |
| 必须实现状态接口 | `GET /api/palace/status` 需返回 200 与合法 JSON |
| 支持跨域 | 若控制台与节点不同域，节点需返回 CORS 允许头 |
| 业务接口一致 | 各节点需部署同一套后端 worker（`/api/*` 端点一致） |

## 4. 行为说明

| 场景 | 表现 |
| --- | --- |
| 多个节点可用 | 自动选择延迟最低者，顶栏显示「就近节点 xxx ms」与节点域名 |
| 当前节点故障 | 下次请求自动切换到下一节点，顶栏显示更新后的节点 |
| 全部节点不可用 | 回退同源，顶栏显示「同源（探测失败）」 |
| 401 | API Key 无效或过期，提示到设置中更新 |
| 403 | 需要管理员 API Key（如 `/api/wallet/keys`） |
| 429 | 请求过于频繁，稍后重试 |

## 5. 常用部署示例

| 场景 | VITE_API_ORIGINS 值 |
| --- | --- |
| 单主域名 | `https://gyuanpalace.xyz` |
| 主域名 + 备用域名 | `https://gyuanpalace.xyz,https://lingdayun.cn` |
| 多边缘节点 | `https://agent.gyuanpalace.xyz,https://node-a.example.com,https://node-b.example.com` |
| 仅同源 | 留空 |

## 6. 验证是否生效

1. 打开控制台，看顶栏连接徽章：
   - 「就近节点 123ms」→ 多端点探测生效；
   - 「同源模式」→ 未配置端点，走当前域名；
   - 「同源（探测失败）」→ 配置了端点但全部不可达。
2. 打开浏览器开发者工具 → Console，无 `所有 API 节点均不可用` 报错即正常。
